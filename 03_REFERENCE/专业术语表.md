## 建模表述与语态

`can` 表达能力或可行性，`is` 构成确定陈述，二者根据句子的实际含义选择。主动或被动语态还须明确陈述的主体、模型对象及作用关系。不得靠增删一个词改变假设、近似或结论的强度。

| 需要表达的含义 | 常用结构 | 使用条件与检查内容 |
| --- | --- | --- |
| 明确定义 | `is defined as`、`denotes` | 本文或引用来源确实给出定义，定义范围和符号一致 |
| 已确认的关系 | `is`、`satisfies`、`is determined by` | 关系有定义、方程、推导或已核查事实支持，必要条件在句中或上下文写清 |
| 本文采用的建模方式 | `is modeled as`、`is represented by` | 明确是当前研究采用的模型，写明适用对象及假设 |
| 为分析设置的假设 | `is assumed to be`、`we assume` | 假设明确列出，并解释其适用条件及对结论的影响 |
| 近似关系 | `is approximated by` | 写明近似条件、参考模型及误差的含义，不将近似写成无条件等式 |
| 方法能力或可行性 | `can`、`can be computed`、`can be solved` | 对所声明的对象、输入条件和范围有推导或验证支撑；具体已完成结果直接报告实际结果 |
| 等价变换或可选表示 | `is equivalent to`、`can be reformulated as`、`can be represented by` | 核对等价条件和变量范围；可选表达形式中的 `can` 也需满足相应条件 |
| 尚未确认的可能性 | `may`、`might` | 作为待验证解释写明，不能据此提出确定的工程结论 |
| 算例观察 | `the results show`、`was observed` 及具体结果动词 | 指明系统、工况、数据和比较条件，保持观察结果的适用范围 |

写作前逐句确认：句子是在给出定义、采用模型、设置假设、使用近似、陈述能力，还是报告结果；随后核对文献、公式、假设或算例依据。按此含义选用谓语及其主动或被动结构。
