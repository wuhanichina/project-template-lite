# 项目禁用词表

本表集中维护项目自编文字中的禁用词、需核对的专业术语和替代表达，适用于研究笔记、论文正文、图注、README、代码注释及任务回复。写入文档前逐句检查，按具体工程对象和原意改写。

## 默认禁用词

| 禁用表达 | 适用语境 | 改写方式 |
| --- | --- | --- |
| 范式、paradigm | 笼统描述研究方法或技术路线 | 写明具体模型、方法、计算方式或工程决策 |
| 径向、径向配电网、径向馈线、径向拓扑 | 描述 radial 电网的接线、馈线或拓扑 | 本项目统一采用“辐射状配电网”“辐射状馈线”“辐射状拓扑”；描述运行方式时写明辐射状运行 |
| 证书、certificate | 将数学可行性或最优性结果写成抽象结论 | 说明检验结果、成立条件、约束满足情况或可核查的上下界 |
| 零空间、nullspace | 用抽象矩阵术语代替工程解释 | 结合实际问题说明不可辨识的参数方向、观测条件或对应矩阵关系，保留必要的数学定义 |
| estimator | 将计算方法或研究对象概括为程序部件 | 写明估计的电气量、系统参数及对应计算方法 |
| 落地、钉死、对齐 | 泛化的行动或协作描述 | 按原意写为实现、确定参数、统一定义、核对结果等具体动作 |

以上为项目默认用词约定。讨论这些用词时可在本表或明确标注的原文引文中保留。参考文献原始题名、标准名称、代码标识符、接口名称和原始数据字段保持原样；英文电力系统术语 `radial` 保留其专业含义。

## 需要核对的数学术语

| 表达 | 使用条件 | 优先写明的内容 |
| --- | --- | --- |
| 算子、operator | 数学对象确有必要，且在推导中已定义 | 对应方程、输入输出关系、物理关系或计算步骤 |
| 可微、differentiable | 可微性影响方法成立条件、求解过程或理论结论 | 哪个模型或函数具有该性质，以及该性质对当前工程问题的作用 |

专业术语根据定义和语境核对，避免机械替换后改变数学含义。经核实的中英文名称、定义、适用条件和来源写入 [专业术语表.md](专业术语表.md)。

## 中文表达检查

- 使用完整句子、完整词语和明确的动宾结构。保留必要的主语、动作及对象，避免单字缩写和自造简称。
- 单独作动词缩写的“崩、挂、判、推、抛”分别按原意写成崩溃、挂起、判定、推断、抛出等完整词语；核对动作及其对象，保持句子成分完整。
- 使用计算、求解、核对、比较、解释、导出、登记和更新等具体动词，避免用“进行”替代实际动作。
- 禁止使用“不是……而是……”“要……而不是……”及同类否定转折句式。用户未要求比较时，直接说明对象、方法和结论，删除虚构的比较对象及结论后的无关否定。
- 电力系统中约定俗成的概念简洁交代，重点解释当前研究缺口、关键假设、方法机理和工程后果；必要定义与成立条件保持完整。
- 控制“物理”的使用频率。需要区分网络关系与统计拟合、说明守恒关系或模型约束时，写清具体对象与含义；其余位置直接使用节点电压、支路潮流、运行约束、模型、参数或机理等准确名称，删除重复修饰。

## 英文套话与空泛修饰

以下表达在自编叙述中默认删去或改写为具体技术内容：navigate、unpack、landscape、deep dive、game-changer、at its core、it is worth noting、it turns out、as we will see、in this section、when it comes to、think about it、here is what I mean。

### 模型常见套话及改写

| 表达及常见变形 | 默认排除的用法 | 改写要求 |
| --- | --- | --- |
| govern、governs、governed、governing | 用抽象动词笼统宣称某变量决定系统或某方程支配过程 | 直接说明变量关系、满足的方程、施加的约束或实际控制作用 |
| delve、delves、delved、delving | 宣布研究将深入某个主题 | 直接说明研究对象、计算任务或待解释的问题 |
| underscore、underscores、underscoring | 反复强调结果的重要性 | 写明结果支持的具体结论及依据 |
| showcase、showcases、showcasing、boast、boasts | 将方法或结果写成展示性、宣传性描述 | 说明计算结果、定量比较及适用工况 |
| intricate、intricacies、realm、tapestry | 用复杂、领域或织物类比替代技术内容 | 写明具体耦合关系、研究对象或系统结构 |
| groundbreaking、transformative、pivotal、crucial | 用程度词替代贡献、必要性或工程价值 | 写清成立条件、解决的问题及可核查的改善 |
| leverage、utilize、harness、unlock | 把一般使用、计算或求解写成空泛的能力描述 | 按实际动作采用 use、compute、solve、derive 或明确的领域动词 |
| holistic、seamless、synergy | 用整体、无缝或协同概括尚未说明的关系 | 写清共同考虑的对象、相互作用及结果 |

条目属于项目写作约定。术语具有明确的领域含义时，按已核实的定义和来源使用，例如专业方法名称中的 robust 或特定工程量名称，保留其实际含义。

收集参考：Tom S. Juzek 与 Zina B. Ward 的 [Why Does ChatGPT “Delve” So Much?](https://arxiv.org/abs/2412.11385)，第 2 节及附录 A、B。该研究记录了部分 GPT 输出中的高频词及词形；本表结合用户指定表达，按项目写作语境列出改写要求。查阅日期：2026-10-29。

significant、structural、fundamentally、inherently、simply、really、every、always、never、all 应有准确的技术含义、明确范围及必要依据。数学定义和有依据的统计表述按实际含义保留。

## 建模语义检查

专业术语和建模表述在使用前查证，要求见 [专业术语表.md](专业术语表.md)。逐句区分定义、假设、建模选择、近似、能力、可能性和算例观察；保留条件及限定词，按照已有推导和结果选择 `can`、`is`、`may` 及相应动词结构。

## 维护

发现新的生造词或翻译腔时，记录原表达、适用语境和具体改写方式；核对专业表达后同步术语表及受影响的正文。文档修改后的检查包括词语匹配与逐句语义核对，按本表规定的语境判断。
