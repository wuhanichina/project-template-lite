# AGENTS.md

本文件规定研究笔记、对外介绍、论文稿件及返修的内容和写作方式。根目录 `AGENTS.md` 的表达、代码和验证约定同时适用。

## 工程动机与研究笔记

- `ProjectName_note.md` 面向电力系统资深工程师和高级研究员，直接进入当前研究缺口。写明实际运行或规划任务、需求与紧迫性、现有方法的输入与假设、工程后果、本文处理的必要性和作用机理。
- 立项和撰写工程动机前读取 `03_REFERENCE/AGENTS.md`，默认联网检索并检索可访问的本地 PowerLit，核对同类问题的常用表达和论述。将文献及中英文术语写入规定的目录和表格。
- 按实际方法族说明已经实现的能力、具体条件下的不足、机理原因及受影响的电气量或决策量。每项方法选择应回应一个已说明的工程缺口。
- 物理机理说明因果关系与可验证预测；模型、算法、控制、理论和数据贡献解释相应模型关系、计算性质、状态响应、成立条件和观测能力。
- 研究笔记呈现当前模型、结果、工程解释和结论。完整推导、符号和结果来源连接到 `01_IDEA/`；开发过程、分支管理和任务安排保存在专门研究或运行记录中。
- 研究目的以 `01_IDEA/story.md` 为人工确认来源，与研究笔记及 `config/paper-profile.yaml` 一致。研究贡献、证据状态或研究目的变化时同步研究内容版本。

## 稿件位置与排版

- Markdown 草稿位于 `manuscript/paper.md`；转入正式写作后主要修改 `latex/main.tex` 及包含的章节文件，保留转稿时的 Markdown 版本。重要模型、公式、符号和结论同步回研究笔记与 `01_IDEA/`。
- `latex/` 包含独立编译所需的正文、`references.bib`、`figures/` 和期刊模板，使用相对路径。默认从一个 Markdown 文件和一个 LaTeX 主文件开始，按实际篇幅或协作需要拆分。
- 读取 `formatting_rules.md`。默认采用 IEEE PES Transactions 适用的官方 `IEEEtran.cls` 和 `IEEEtran.bst`，保持上游文件内容。目标期刊的明确要求优先。
- 保留 `\markboth` 页眉及默认页码，随稿件更新期刊名称、作者简称和论文短标题；卷期与出版日期确认后填写。
- 公式按句意使用标点。逗号结尾、后文续接同一句时不留空行或插入 `\par`，续接文字不作首行缩进。公式处句子结束时使用句号；确实另起段落时采用模板正常缩进。避免全局取消缩进或强制所有公式使用逗号。
- 稿件用图从 `result/<case>/figures/` 的正式导出中选取，复制到 `latex/figures/`，在证据索引中维护来源和稿件路径，结果图更新时同步副本。数据、FIG、manifest 和检查报告留在结果目录。
- 当前论文引用条目维护在 `latex/references.bib`，Markdown 引用键与其一致；文献原文和阅读材料进入 `03_REFERENCE/`。
- Git 跟踪稿件源文件、文献、模板和稿件用图，忽略编译中间文件。配置 Overleaf 同步时明确 `latex/` 与 Overleaf 项目根目录的对应关系，获取最新修改并处理冲突后推送；按用户要求配置同步。
- 真实作者资料仅放在 Git 忽略的 `config/author-profile.yaml` 中，仓库跟踪示例文件。

## 引言与结果论述

- 文档写入前逐句检查专业用词，清除生造词和计算机、数学翻译腔，采用电力系统论文中的通用表达。约定俗成的概念简洁交代，重点解释本文特有的研究缺口、假设、机理和工程后果；必要的符号定义与成立条件保持完整。
- 引言从具体运行或规划任务及其后果进入，保留理解当前缺口所需的背景。随后评述代表性方法、解释机理原因、说明本文模型与方法及其工程作用，再组织必要的验证说明和贡献。
- 创新点说明发现或验证的判断、提出的模型或方法、理论意义、工程价值、解决的工程问题及支持证据。数学形式和软件能力本身须与声明的研究对象建立联系。
- 原理、假设、输入条件、方法和结论均以已核实材料为依据。缩略语、内部配置名和版本标识放在对应记录中，正文使用同行能够识别的名称。
- 结果分析围绕图表对应的工况、可见规律、定量差异、物理或运行原因、解决的问题和工程效果展开。涉及适用条件时写明其对当前结论的影响。
- 论文文字从研究笔记、推导、结论、登记结果及核查文献组织。对外介绍提供叙事参考；稿件中的事实与判断逐项核对其原始依据。

## 对外介绍

- `ProjectName_blog.md` 的叙述由确认的创新轴、技术对象类型、叙事顺序、创新幅度和研究阶段决定。推荐从真实工程场景进入，解释关键关系、已有不足、本文处理、结果和工程含义。
- 区分研究对象、应用场景和证据场景。算例、地区或事件名称用于说明验证条件；当模型与输入确实依赖该场景时，再将其写入方法定义。
- 可依次说明工程直觉、参照方法、具体原因、关键条件、本文处理和最强结果。每段增加新的技术内容，工程含义保持在已有系统、工况、数据和假设范围内。
- 内部创新分类、结论编号、证据编号及状态保存在研究档案中，正文采用连续的专业论述。重要判断连接适用范围、来源和相应证据状态。

## 交接与返修

写作或评审前读取：

1. `ProjectName_note.md`、`ProjectName_changelog.md`。
2. 本目录的论文配置与本地作者配置，缺失时读取对应示例。
3. `01_IDEA/story.md`、`claims.md`、`derivation.md`、`symbols.md`、`evidence_map.md`、`research_trace.yaml`、`figure_plan.md`。
4. 与当前判断相关的运行和图表 manifest、原始结果、绘图数据及检查报告。
5. 当前 Markdown 或 LaTeX 源文件及 `references.bib`，相关文献目录和专业术语表。
6. 返修时的 `revision/` 材料；涉及对外介绍时核对相应叙述及原始依据。

PowerLit 交接读取 `.cursor/contracts/project-template-handoff.schema.yaml`，论文配置的 `contractVersion` 与合同一致。Skill 负责研究判断和写作推理，项目维护确认值、运行事实、结果和返修状态。

返修涉及主张、机理、假设、证据或图表解释时，同步 `revision/`、当前稿件、`01_IDEA/claims.md`、研究笔记及研究内容版本。回复说明准确的文件、章节、公式、图表和证据；核对正文及结果后更新完成状态。

证据状态使用：`已由理论推导支持`、`已由数值实验支持`、`已由代码实现支持`、`已有 Git 版本记录`、`仅为当前假设`、`尚未验证`、`结果不稳定`、`当前证据不足`、`已被实验排除`、`暂时放弃`、`文献待核查`、`代码尚未实现`、`结果待复核`。详细状态登记在结论和证据文件，必要的未知信息明确写入对应记录。
